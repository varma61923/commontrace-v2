# Ingestion/parser/SQL audit, phase 6

Source freeze: production edits in `commontrace/ingest/`, `commontrace/sql_guard.py`, and the explicitly approved `commontrace/fingerprints.py` extension were frozen after the targeted regression, Ruff and medium/high Bandit gates below. Baseline source is **c8ce5c792916c10e23b0618c59259960294b7bcc**. No dependencies, retrieval defaults, model APIs, judges, memory artifacts, commits, or pushes were changed by this workstream.

## Confirmed findings and changes

- `TextChunker` copied the remaining paragraph after each 2,000-character split. An ordinary 4 MiB text file could copy gigabytes cumulatively. Offset-based paragraph/chunk iteration removes the quadratic copying and materialized paragraph list, retaining existing chunk IDs, metadata, paragraph/overlap behavior. Invalid nonprogressing chunk sizes are rejected. Multimodal long words and oversized DOCX paragraphs now split into bounded chunks as well.
- Malformed PDF `BT` regions, repeated escaped opening parentheses, unclosed HTML script blocks, and unclosed contextualizer role tags all caused repeated scans of the remaining input. Forward scanners, HTMLParser, and merged role-tag spans remove these demonstrated quadratic cases. HTML script/style/noscript contents remain suppressed when unclosed. Nested closed role blocks are completely stripped. Malformed escaped PDF opening parentheses outside strings are ignored; valid escaped parentheses/backslashes inside strings retain their meaning. PDF extraction remains a heuristic text extractor, not a full PDF renderer.
- Text, log/transcript, subtitle, image/audio and PDF reads previously relied on a size check followed by an unrestricted or separately opened read. A substituted symlink/FIFO or growing file could escape that check. Readers now pin ancestor directory descriptors, open leaves with `O_NOFOLLOW|O_NONBLOCK`, verify regular-file type and opened size, and enforce actual read bounds. DOCX uses the same protected descriptor, caps inflated XML, rejects DTD/entities (including UTF-16/32 NUL-padded markup), streams/clears elements, and applies 200,000-element/256-depth ceilings. Invalid XML no longer falls through to a potentially quadratic regex parser. Legitimate nested Word text-box paragraphs retain the original pre-order/content extraction; aggregate extracted characters are also bounded to prevent nested-content duplication from amplifying output.
- Ledger hashing opened paths independently and could follow a replacement or read growing input indefinitely before an ingestion size check. The approved `stream_fingerprint` preserves existing full/sample hash formulas; protected ledger callers hash pinned regular files under the correct text/multimodal size ceiling. Full hashing rejects growth/shrinkage relative to opened size. Unchanged checks include device/inode/ctime in addition to size/mtime; legacy rows lacking that identity rehash. Ingested outcomes preserve staged source identity/fingerprint, so replacements after loading are retried instead of marked as ingested under newer metadata.
- `get_document` previously reread an arbitrary uncataloged raw path. It now returns registered snapshots only, using valid manifest IDs or registered source paths, with bounded regular-file manifest/body reads. Previously ingested external sources remain retrievable as snapshots. Payload writes atomically replace leaves through pinned directory descriptors and serialize body/manifest publication under the manifest lock. Two same-ID writers cannot publish mismatching final metadata/body. A leaf symlink is replaced without modifying its target.
- The registry check uses an immutable cache, validated by device/inode/mtime/ctime/size on pinned descriptors. Generation tokens prevent older parses from publishing over newer loads. Retention is bounded by eight roots, 50,000 aggregate ID/source entries and 16 MiB of ID/path UTF-8 bytes; larger registries serve uncached. Caller mutations cannot pollute cached registry/body results.
- SQL comment stripping changed literal data, LIMIT rewriting modified nested clauses and missed negative/expression/comma limits, PRAGMA virtual tables bypassed keyword checks, and a single `randomblob` invocation could allocate before the VM progress timeout. A quote-aware scanner preserves literal/identifier data; only outer integer LIMITs are clamped, other outer LIMIT forms are safely wrapped. A SQLite authorizer denies non-read actions, PRAGMA tables and extension/file functions, in addition to read-only URI and `query_only` mode. Python 3.11+ applies a 1 MiB SQLite value/row limit, 64 KiB SQL limit, 128-column and 100-expression-depth limits. Results have an 8 MiB conservative accounting budget (cell data plus estimated Python container/value overhead), and requested rows are capped at 10,000 before connection creation. The default remains 100.
- Python 3.10 lacks `sqlite3.Connection.setlimit`; its fallback authorizer permits ordinary SELECT/count/numeric analytics and rejects allocation-heavy functions and aggregates through an explicit conservative allowlist. The simulated no-setlimit regression covers preserved count queries and denied randomblob/group_concat/printf calls.

Results are medians of three local runs; malformed/parser speedups are adversarial microbenchmarks, not throughput claims for ordinary documents. This excludes the already allocated input and excludes callers that retain all yielded chunks. Baseline cProfile attributes nearly all long-paragraph work to `_chunk_text`; post-change iteration scales approximately linearly. The 8 MiB direct/API input is above the 4 MiB text-file ingestion ceiling. No universal 20x claim is supported.

## Validation and limits

Targeted gate: **228 passed in 4.11s**. `python -m pytest tests/test_ingestion_security_phase6.py tests/test_ingest_pipeline_v2.py tests/test_ingest_ledger.py tests/test_ingest_connectors.py tests/test_ingest_catalog.py tests/test_multimodal_ingest.py tests/test_provenance_ingest.py tests/test_sql_guard.py tests/test_security_remediations.py tests/test_storage_remediations.py tests/test_subprocess_security.py -q`.

Ruff: `ruff check commontrace/ingest commontrace/sql_guard.py commontrace/fingerprints.py tests/test_ingestion_security_phase6.py research/ingestion-security-phase6-benchmark.py` passed. Bandit medium/high gate over the owned production files passed. Two narrow suppressions explain DTD-rejected/bounded stdlib XML parsing and intentional wrapping of already validated read-only SQL.

These changes bound the demonstrated input/expansion/result amplifications; they do not impose a total process RSS ceiling. SQLite sort/aggregate workspaces, existing database payloads, Python Unicode/object overhead and parsing of the largest accepted registry can still consume more than the named byte budgets. Python 3.10 cannot enforce SQLite scalar/row size limits, so reading very large preexisting database values has weaker memory guarantees despite the conservative function policy. VM progress callbacks interrupt repeated query operations, not every individual SQLite C operation. SQLite database opening still uses a pathname; it is not proven safe against a concurrent hostile local filesystem actor swapping that path, and no `/proc` descriptor workaround was added because live WAL semantics were not established.

Descriptor protection relies on the POSIX `dir_fd`, `O_NOFOLLOW`, and directory-open support available in the tested Linux deployment. Source content can still be modified in place during a read; pinning guarantees inode/path selection, not a transactional source snapshot. Store-wide JSONL job/ledger/listing writers remain on the existing shared `_jsonl` implementation; this patch does not claim to make every store operation safe under hostile mutation of the store directory by another local user. Full repository validation and CI monitoring are owned by the root agent.
