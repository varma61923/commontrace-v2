# 0020: Corrections and asking use canonical outcomes

A human correction is governed source-linked content, not an automatically
trusted demonstration. Its baseline and windows commit before the canonical
outcome under the outcome-file lock. Quality uses fixed blocks with an alpha
spending schedule, and remains a downstream residual diagnostic. It does not
identify a causal operator effect or attest physical execution. Review and
appeal bind the exact report; a corrector cannot approve their own training data.
The RL boundary checks this hold before bytes and between streamed shards.

Asking randomization is explicitly enabled only for enrolled low-risk contexts,
using real typed assignments and logged propensities. Shared fleet reservations
commit before drawing either arm and outlive content erasure. Failed or pending
requests cannot overspend or refund the budget. Effects require complete
canonical cohorts and actual reported time; model priors and planner scores
remain separate. Empirical-Bayes calibration uses other completed scoped trials
and carries erasure links into the learned policy.

ROS uses a real generated service definition, with a per-robot default service
name and a bridge-bound task context. The surrounding authenticated DDS graph
and configured callback own client authorization. Optional native tests are
explicitly skipped when the ROS toolchain is absent.
