# CrewAI async callback behavior

CrewAI 1.15.27 does not provide an awaitable path for `before_kickoff_callbacks` or `after_kickoff_callbacks` in native `Crew.akickoff()`. Its shared `prepare_kickoff()` loop calls each before callback directly and assigns the result (`crewai/crews/utils.py:302-305`); `Crew.akickoff()` likewise calls each after callback directly and assigns the result (`crewai/crew.py:1286-1287`). Returning a coroutine would therefore pass an unexecuted coroutine on as kickoff inputs or output. `commontrace/framework_middleware.py` should keep these callback adapters synchronous until CrewAI exposes and awaits async callbacks.

CrewAI's `Crew.kickoff_async()` is a supported event-loop-safe option for these synchronous callbacks: its non-streaming implementation delegates `self.kickoff(...)` to `asyncio.to_thread` (`crewai/crew.py:1187`). Use `await crew.kickoff_async(...)` when CommonTrace callbacks need synchronous retrieval or persistence and the caller needs its event loop to keep running. Native `await crew.akickoff(...)` still blocks the loop while those callbacks execute.

The local competitor examples do not add a native async kickoff callback path. Hindsight's CrewAI storage adapter has synchronous `save()` and `search()` methods in `hindsight-integrations/crewai/hindsight_crewai/storage.py:161-166, 207-215`; Mem0's CrewAI example retrieves and injects memory before `crew.kickoff()` in `skills/mem0/references/integration-patterns.md:86-108`; Zep's CrewAI memory search tool implements synchronous `_run()` in `integrations/crewai/python/src/zep_crewai/tools.py:442-467`. These support the synchronous memory integration pattern but do not solve `akickoff()` event-loop blocking.

`tests/test_optional_crewai_lifecycle.py::test_crewai_kickoff_entry_points_with_callbacks` exercises all three entry points with deterministic blocking callbacks. It verifies ordinary `kickoff()` still injects and captures memory, `kickoff_async()` keeps a loop heartbeat running during both callbacks, and native `akickoff()` leaves the loop stalled during them. The test sets `CREWAI_DISABLE_TELEMETRY=true` before importing CrewAI. In 1.15.27, the telemetry singleton checks this variable during initialization and returns before registering its exporter shutdown callback with `atexit`, allowing the optional runtime check to exit cleanly without changing application telemetry behavior. The test passed against the installed package with a scripted local LLM and no service credentials.
