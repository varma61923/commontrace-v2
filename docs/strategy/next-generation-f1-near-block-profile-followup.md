# F1 near-block profile follow-up

Graphify confirmed that the acceptance workload reaches `FactStore.StatementIndex.near()` from `hierarchical.add_facts()`; its graph shows the path through `_link_entities_best_effort()`, though the benchmark statements produce no entities. `benchmarks.next_generation_storage.statement()` assigns a distinct number to each item, so the block-presence probe is exercised while token-frequency candidate reads return early.

The competitor graphs show Graphiti's `add_nodes_and_edges_bulk()` handing its grouped records to one transaction callback and Hindsight's `fact_storage.insert_facts_batch()` serving several batch-retain callers. CommonTrace already batches its FTS and term projections during flush. Those persistence examples did not change the diagnosis: the remaining candidate was the per-statement near-block precheck, which matches the earlier rejected experiment.

A 10K-store `cProfile` of one 1,000-fact batch recorded 1,000 near lookups and 1,000 indexed block probes. The point-probe path took 0.73469 seconds (1,361.1 facts/s under the profiler); `_add_locked()` accumulated 0.467 seconds and `StatementIndex.near()` 0.055 seconds. A diagnostic implementation batched the block checks, then used the returned absent/present set to skip point probes. It made 995 fewer SQLite `execute()` calls, but its prefetch itself cost 0.047 seconds and the profiled batch took 0.73550 seconds (1,359.6 facts/s). The candidate therefore did not improve this measured batch.

This is the same approach previously rejected in [the original near-block experiment](next-generation-f1-near-block-prefetch.md): group up to 200 numeric/negation blocks per query, replacing 1,000 point probes with five prefetches. That matched 30K run measured 2,291.688 facts/s before and 2,261.888 with the candidate. A new matched on/off diagnostic at 30K was noisy: the two point-probe rounds measured 2,105.999 and 2,161.421 facts/s; the prefetch rounds measured 2,271.654 and 2,129.233. Their spread does not establish a lift. A standalone candidate run measured 2,175.902 facts/s; its report and integrity sidecar are at `/tmp/f1-near-block-prefetch-candidate-30k.json` and `/tmp/f1-near-block-prefetch-candidate-30k.json.sha256`.

I removed the repeated prefetch implementation and retained a contract test for near matches staged earlier in one batch, dissimilar siblings sharing a numeric block, and a later lookup selecting the matching fact. These diagnostics are not 1M acceptance evidence; the ≥2,000 facts/s gate remains open.
