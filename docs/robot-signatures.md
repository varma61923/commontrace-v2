# Force and proprioceptive signatures (G24)

The edge signature path summarizes joint current, force/torque, tactile and temperature channels. Profiles are grouped by skill, embodiment, site, task phase, payload class and firmware. Each channel stores median, MAD-derived scale and an empirical residual quantile cutoff. Arrays are capped at 256 downsampled values. `robotics.ingest.mcap_file` and `ingest_records` accept an `on_record` callback so an MCAP/LeRobot integration can route its proprioception fields into the signature ingest path; `robotics.bridge.signature_sample_handler` connects live robot callbacks to checks.

`unimem fleet signatures build|check|drift` and MCP `signature_check` expose the core. An exceedance creates a bitemporal anomaly memory linked to its episode and a recovery registry entry that asks for qualified inspection. It does not diagnose a component or authorize an action. Drift queries compare medians across firmware boundaries and return estimated shifts with event and record times.

The false-alarm target is an empirical per-channel quantile, not a finite-sample guarantee. Calibration assumes representative nominal samples for each profile key. Missing profiles fail closed for diagnosis. Optional quantile-forecast plugins can be registered through `register_forecaster`; the core includes no Chronos dependency. Published work on time-series foundation models does not establish validity on robot joint/current data, so forecast output remains a model estimate and must not replace measured bands or robot safety functions.
