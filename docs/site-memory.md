# Collective site memory (G26)

The local `robotics.vda5050` module validates bounded state, zone and order messages for version 3.0.0. Order-route edges become path events with checked optional shared-edge references. `unimem fleet site ingest` accepts `message_type: state|zone|order`. For example, pass `{"message_type":"order","message":{"headerId":1,"timestamp":"2026-06-20T14:05:00Z","version":"3.0.0","manufacturer":"vendor","serialNumber":"r-1","orderId":"order-9","orderUpdateId":1,"nodes":[{"nodeId":"dock","sequenceId":0,"released":true}],"edges":[]},"site":"depot","robot":"r-1"}` as its JSON request. This is a small interoperability subset written from the public field model, not a complete VDA conformance schema. The Open-RMF adapter boundary accepts an injected `to_unimem_state` mapping so the core has no RMF dependency. That contract is tested for required fields, canonical timestamps, bounded node/edge/zone counts, scope filtering and rejection without partial writes. Native RMF message and transport bindings remain deployment-owned and unverified. Both adapters feed vendor-neutral bitemporal site events.

`site_memory.scene_graph` merges robot observations by node/object layer and keeps sensor source, event time and record time. Conflicting frames stay as separate layer observations. `site_memory.rules` estimates hourly zone congestion with a normal-approximation interval; it emits review text only. `suggest` records a review-required site suggestion and never sends a route command.

`mesh_crdt` uses per-robot Ed25519-signed operations and a locally pinned robot-key registry. The reference reducer implements an observed-remove set and multi-value registers. Conflicting concurrent values become explicit contradictions. Safety adds cannot be removed. Unknown, forged and revoked peer operations are rejected and tainted; revocation also excludes historical operations from merged views. Run `unimem fleet site ingest|merge|rules|mesh` for the CLI workflows. Install `unimem[crdt]` for signature support.

With `unimem[crdt]` on Python 3.12+, Automerge 0.2.0.dev4 merges peer operation-list documents before the deterministic UniMem reducer enforces safety and semantic-conflict policy. The reference reducer remains available on Python 3.10/3.11 where that prerelease wheel is not published. The pinned Automerge version is a development release, so its document API and binary compatibility remain unverified against other language bindings. Mesh operators must exchange key registries and revocations through an authenticated channel. VDA/RMF mapping coverage is limited to the repository's own fixtures and the documented field subset; robot motion and routing remain under the fleet's certified control stack.
